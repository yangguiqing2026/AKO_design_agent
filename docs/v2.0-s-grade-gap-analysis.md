# S 级（v2.0）差距分析与迁移路线（Sprint 3 收官）

> 定位：白皮书 §1.4 架构师评估「A 级认证工程治理，S 级认证 AI 原生解决复杂不确定性的能力」——
> 从 v1.0.1-S3（维度V=8/10、总分 83.84、L2.5）到 S 级的差距逐项登记与迁移顺序。

## 差距矩阵

| # | 差距项 | 当前状态（v1.0.1-S3） | 目标版本 | 验收口径 | 依赖/前置 |
|---|--------|----------------------|---------|---------|-----------|
| 1 | 语义向量检索 / embedding | 仅统计版权重（pattern-weight 0.5–2.0 乘性），无语义召回 | v1.5 | 案例相似召回命中率基准（金种子子集） | 向量库选型（Qdrant/Pinecone）、embedding 服务 |
| 2 | 离线金种子评测集 | 无；critic/validator E2E 为规则/沙箱自检 | v1.5 起步 / v2.0 闭环 | ≥85% 需求结构化、≥90% 模式匹配、100% schema 通过（§10.1） | 人工标注集（100 条需求 / 50 场景） |
| 3 | Actor-Critic 完整版 | Critic-Executor 简化版 + 统计权重更新（无 RL） | v2.0 | 沙箱报错自动修复成功率门禁；奖励信号可追踪 | 金种子集 + 沙箱回放 + LLM evaluator seam |
| 4 | 约束求解器 | requirement.performance 解析 + max_steps/tool_call/timeout 预算，无向量空间最优化 | v2.0 | 非功能指标（并发/延迟/成本）组合最优解输出 | 指标建模 + 求解器选型 |
| 5 | OpenTelemetry | 结构化 JSON 日志 + trace_id（logger） | v1.5 | Jaeger 导出与跨会话追踪 | OTel SDK 依赖（需批准） |
| 6 | 语义适配器（DSH 多版本 API） | 单一归一化契约（Cordis-4 cordis-agent.interface）+ legacy 标注 | v2.0 | 多版本 Harness API 同一领域面 | 真包私有源闭环环境 |
| 7 | 真实 LLM 在线生成 | 仅 PromptAssembler + ProfileGenerator seam（无在线调用） | v2.0 | 金种子集在线生成比对 | API 凭据 + 成本预算接入（costCircuit seam 已就绪） |
| 8 | 真实 MCP SDK/协议 | ToolBridge 抽象 + LocalToolBridge（进程内） | v2.0 | list/call 与标准 MCP client 互通 | MCP SDK 依赖（需批准） |
| 9 | TTFT / 时间熔断真机压测 | time-circuit 100% 熔断单测；live 探针 gating（AKO_TTFT_LIVE） | v1.5 | P95 TTFT ≤ 配置阈值；超限 100% 中断 | 受控网络/凭据环境（docs/time-circuit-validation.md 待回填） |

## 迁移路线（建议顺序）

1. **v1.5 先行**（向量/评测/OTel/TTFT 压测）：补齐可度量基线与观测底座 —— 差距 #2 → #5 → #9 → #1。
2. **v2.0 S 级闭环**：以金种子离线评测（#2 完成态）为门禁，接入真实 LLM（#7）+ Actor-Critic（#3）+ 约束求解器（#4）；语义适配器（#6）随真包源就绪演进；MCP SDK（#8）随工具外部化需求接入。
3. 每个迁移项均需在 `.ako-compliance-report.md` 追加证据与测试映射，杜绝“无证据提分”。

## 收口约定
- 本仓库默认 CI **不依赖** 真实网络/凭据/真包（`AKO_DSH_LIVE=1`、`AKO_TTFT_LIVE=1` 显式开启）。
- 维度分数只在「落地证据 + 测试映射」齐备时调整；差距项在报告内持续跟踪直到 v2.0。
